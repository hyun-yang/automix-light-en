This isn't a test. The reason matters more than the label.

How do automix-light's outputs fit the software development life cycle (SDLC)?

The software development life cycle (SDLC) is the process of planning, building, checking, and improving software. Here's what automix-light keeps along the way.

You still only need new and go to start. go includes checking and reviewing. review and rule below are optional helpers; you don't need to learn them now.

On a small screen, scroll inside the table from side to side. With a keyboard, use Tab to reach the table, then the ← → keys to move across it.

1 · Project guidance AGENTS.md is a project guide for the tool. Claude Code uses CLAUDE.md. Guidance files are prepared if missing, rather than recreated every time. Mockups are made when comparing screen designs would help.

2 · How checks work Codex defaults to a self-check by the AI that did the work. A check is recorded as independent only when it was actually assigned to a separate helper. Read the progress notes to see what was checked and what couldn't be checked. See how checking differs between tools.

Unfamiliar words Completion criteria are “the things to check before calling it done.” A rule card is “a document of agreements that help prevent repeated mistakes.” For code, files, mockups, testing, review, git, commits, and the full name of SDLC, see the plain-language glossary.

I found an unfamiliar word. What does it mean?

Hover over or press a dotted-underlined word in the text to see its meaning. With a keyboard, use Tab to reach it, then Enter or Space to open the explanation and Esc to close it. Pressing the same word again or pressing elsewhere also closes it.

Code
Written instructions that tell a computer what to do. In this guide, the AI writes them. You don't need to know how to read or write code before you begin.
AI
Here, a program you can talk to that helps plan and build things. Its suggestions and results can be wrong, which is why checking matters.
Codex
The AI work tool used for the examples in this guide. With automix-light installed, you can ask it to follow a planning and building process in chat.
File
A document stored on a computer. Files ending in .md usually contain written notes. A file ending in .html, like this guide, can be opened in a browser.
Screen mockup
A sample screen used to compare looks and layouts before building. It might show buttons without being a working app.
Verification · Testing
Actually checking whether something does what you agreed. For example, adding a task and checking that you can mark it done.
Review
Looking again for mistakes, missing pieces, or things that don't match the plan.
git · Commit
git is a tool for keeping a history of changes. A commit records one batch of work. It helps compare or return to earlier work, but it can't undo every action, such as information already sent elsewhere.
SDLC · Software Development Life Cycle
An industry term for the whole process of planning, building, checking, and improving software. You don't need to memorize the name. Follow the steps in this guide instead.
What's the difference between a self-check and an independent check?

Self-check

The AI that did the work starts again from the agreed completion criteria and checks the result. This is the default in Codex.

Independent check

A separate helper takes a fresh look. It is recorded as independent only when the check was actually assigned to that helper.

The Claude Code version includes a step to call a separate checking helper. Copilot CLI also calls a separate helper; if the check couldn't be assigned, it records a self-check instead. In either case, look for what was actually run and checked.

Protection against risky actions also differs between tools. The Claude Code and Copilot CLI versions have AML-specific controls for some actions. Codex doesn't have the same AML-specific controls; Codex's own permissions and approval settings depend on the environment. Copilot may also let an action proceed if its control takes too long to run. The tools don't all guarantee the same protection.

I'm stuck, or work has stopped. What can I say?
  • When the explanation feels unfamiliarI've never built an app before. Please use plain language and explain one thing at a time.
  • When you don't know what to chooseI'm not sure. Please recommend something for my situation and explain why.
  • When you don't know why work stoppedPlease tell me where we're stuck and whether you need anything from me.
  • When you want to continue in a new conversationPlease read this project's plan and progress notes, then tell me what's left to do.

Stay in the same project folder. After checking the plan and progress, you can continue with $aml:go. If the AI asks you to make an important choice, read the reason and answer it.
